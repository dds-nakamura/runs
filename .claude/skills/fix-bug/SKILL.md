# テストファーストの不具合修正

テストを先に固定し、エージェントがテストを書き換えられない状態で直す。直った証明はそのテストの成功。

## 手順

1. **原因調査（推測禁止）**: 再現手順・panic メッセージ（`RUST_BACKTRACE=1`）・ログ・該当コードから根本原因を特定し、
   根拠（出力の行・コード行）を示してユーザーに説明する。症状ではなく原因を直す
2. **再現テストを書く**: 既存テストの流儀に合わせる。**ロックするため、テストは実装と別ファイルに置く**
   （Rust の慣習どおり同じファイルの `mod tests` に書くと、ロックで実装も直せなくなる）
   - 内部ロジック: `src/foo.rs` に `#[cfg(test)] mod tests;` を置き、`src/foo/tests.rs` に書く
     （`src/foo/mod.rs` 形式なら `src/foo/tests.rs`）
   - 公開 API・CLI の挙動: `tests/<機能>.rs`（結合テスト）
   - 描画の不具合: `/tui-test` の描画テスト
3. **失敗を確認**: `cargo test <テスト名>` を実行し、**不具合そのものが原因で**失敗していることを確認する
   （コンパイルエラーや環境要因の失敗は不可）。出力を示す
4. **ロック**: `node .claude/scripts/test-lock.mjs on <テストファイル> --reason <issue番号>`
   以降、そのファイルはフックにより編集できない（`mod tests;` の宣言行は実装側にあるので消さない）
5. **修正**: 実装側だけを直す。テストが誤っていると判断したら、修正を止めて根拠を報告する
6. **証明**: 追加テストが成功し、`bash .claude/scripts/verify.sh` が VERIFY OK になることを出力付きで示す
7. **解除依頼**: ユーザーに `! node .claude/scripts/test-lock.mjs off` の実行を依頼する（エージェントは解除できない）

テストのコミットは、テスト（失敗状態）→ 修正 の順に分けると、差分から「直ったこと」が読める。
