# Intent: 設定したコマンドを一覧から実行し、出力を見て、停止できるようにする

- 課題: #5 https://github.com/dds-nakamura/runs/issues/5
- 作成者: nakamura_kouji / 状態: approved
- 対象: メイン画面（#1 のプレースホルダーを置き換える）、設定ファイルの読み込み、子プロセスの実行

## 課題（Problem）

開発中は、ビルド・テスト・開発サーバーの起動などのコマンドを 1 日に何度も実行する。いまは次のことが面倒になっている。

- コマンドをその都度シェルの履歴から探して打つ。プロジェクトごとにコマンドが違い、長いものは覚えていない
- 開発サーバーのような終わらないコマンドは別のタブで動かすため、どのタブで何が動いているか分からなくなる。止め忘れが起きる
- 複数のコマンドを並べて動かすと（サーバーを動かしたままテストを流す）、どの出力がどのコマンドのものかを追いにくい

`runs` は #1 で起動・終了・端末復元の土台ができたが、アプリの機能はまだ無い。

## 目指す結果（Proposed outcome）

プロジェクト直下に置いた設定ファイル（TOML）に登録したコマンドを、`runs` の 1 画面から選んで実行し、出力を見て、止められる。完了は次で判定する。

- プロジェクトのディレクトリで `runs` を起動すると、設定ファイルに登録したコマンドが名前付きで一覧される
- 一覧からコマンドを選んで実行すると、その出力（stdout と stderr）が画面に流れ、終了したら終了コードが分かる
- 終わらないコマンド（開発サーバー）を動かしたまま、一覧の操作と別のコマンドの実行ができる
- 実行中のコマンドを一覧から選んで停止できる。停止後にそのプロセス（子プロセスを含む）が残らない
- 複数のコマンドが同時に実行中でも、一覧で各コマンドの状態（未実行・実行中・終了コード）が分かり、選んだコマンドの出力だけが表示される
- `q` / Ctrl+C で `runs` を終了すると、実行中のコマンドをすべて停止してから終了する。端末は #1 と同じく復元される
- 設定ファイルが無い・壊れている・コマンドが起動できないときは、何が悪いかが読めるメッセージが出る（端末が壊れない）
- コマンドの出力に含まれる制御文字で画面が壊れない

## 影響する利用者・環境

- 利用者: 開発者本人（複数のプロジェクトを行き来し、WSL と Windows の両方で作業する）
- 一次対象: Windows 11（Windows Terminal）/ Linux / macOS。実機確認は Windows Terminal と WSL の Ubuntu 24.04。macOS は未検証とする
- 実行するコマンドの例: `cargo test`、`npm run dev`、`go run ./cmd/server`、`bash .claude/scripts/verify.sh`

## 制約

- 設定ファイルはプロジェクト直下に置く。形式は TOML（依存クレートの追加が要る。spec で合意する）
- 複数のコマンドを同時に実行できる
- `runs` の終了時は実行中のコマンドをすべて停止してから終了する（確認は出さない）
- #1 で決めた土台を保つ: 状態・更新・描画を分け、端末なしでテストできる。端末に触るのは `tui` と `main` だけ。
  `q` / Ctrl+C で終了する。`--version` / `--help`、非 TTY のエラー終了の挙動は変えない
- `rust-safety` を守る。特に 3 章（外部入力の表示: コマンドの出力は信頼できない）、6 章（外部コマンド: 利用者の入力を `sh -c` に連結しない。
  パスは `Path` で扱う）、7 章（TUI 実行中に stdout / stderr へ出さない）
- 外部サービスとの連携は無い（`gh` 経由の機能は別 issue）
- 期限は無い

## 範囲外（別 issue）

- 実行履歴の保存、`gh` 経由の PR・CI・課題の表示、複数リポジトリの git の状態、AI エージェントの監視、設定の編集 UI
- 設定ファイルをグローバル（OS の設定ディレクトリ）にも置けるようにすること
- 終了時に実行中のコマンドがあるときの確認ダイアログ
