# Intent: 日常で使うための仕上げ（実行時刻と所要時間、設定の再読み込み、停止して再実行）

- 課題: #7 https://github.com/dds-nakamura/runs/issues/7
- 作成者: nakamura_kouji / 状態: approved
- 対象: メイン画面の一覧と出力欄、キーバインド、設定の読み込み、イベントループ

## 課題（Problem）

#5 で、登録したコマンドを実行・停止できるようになった。毎日の作業で使い始めると、次のことが引っかかる。

- 一覧を見ても「このテストはいつ動かしたのか」「どれくらいかかったのか」が分からない。`exit 0` が 1 分前なのか昨日なのか区別できない
- 実行中のコマンドがどれくらい経ったか分からない（固まっているのか、長いだけなのか）
- `runs.toml` を直すたびに `runs` を終了して起動し直す必要がある。動かしている開発サーバーも一緒に止まる
- 開発サーバーを再起動するのに `s` → 終了を待つ → `Enter` の 3 手順かかる

## 目指す結果（Proposed outcome）

- 一覧の各コマンドに、前回の実行がどれくらい前か（例: `3m ago`）と所要時間（例: `1m 12s`）が出る。実行中は経過時間が毎秒進む
- `r` を押すと `runs.toml` を読み直し、一覧が新しい設定に変わる。実行中のコマンドはそのまま動き続け、同じ名前のコマンドは状態・出力・実行時刻を引き継ぐ。
  設定から消えた実行中のコマンドは停止する
- 再読み込みで設定が壊れていたら、一覧はそのままにして、理由が画面の中で読める（`runs` は終了しない）
- 実行中のコマンドに `Enter` を押すと、確認なしで停止してから再実行する。出力は再実行のものに置き換わる
- 上記を加えても、#1・#5 で決めた挙動（終了・端末復元・停止・非 TTY・`--help`）は変わらない
- 待機中に CPU を使わない状態を保つ（毎秒の更新は実行中のコマンドがあるときだけ）

## 影響する利用者・環境

- 利用者: 開発者本人
- 一次対象: Windows 11（Windows Terminal）/ Linux / macOS。実機確認は Windows Terminal と WSL の Ubuntu 24.04。macOS は未検証とする

## 制約

- 時刻は経過で表す（`3m ago`）。絶対時刻（`14:32`）は出さない → ローカル時刻のクレート（chrono / time）を入れない
- 再読み込み時に実行中のコマンドは止めない（設定から消えたものだけ停止）
- 再実行は確認なし。自分専用の道具なので誤操作は許容する
- 左ペインの幅は画面幅の 40% までのまま（#5 の設計）。表示項目が増えて入りきらないときの扱いは spec で決める
- #5 の構成を保つ: 状態・更新・描画の分離、`runner` だけがプロセスに触る、テストは実装と別ファイル
- `rust-safety` を守る（特に 4 章: 経過時間の計算で `Instant` の差を取る。`u16` の引き算を書かない）
- 依存クレートの追加は spec で合意してから。現時点では不要と見込む（`std::time::Instant` で足りる）
- 期限は無い

## 範囲外（別 issue）

- 行単位のスクロール、出力の検索、色付き出力、実行履歴の保存（`runs` を終了すると時刻・所要時間は消える）
- `runs.toml` の変更を検知して自動で再読み込みすること
